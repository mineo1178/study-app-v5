## 2. カードの意味と紐づけ

`CURRICULUM_PRESETS.math` の「計算」には①〜⑦が登録され、`addUnitWithPresets` は各項目に別々のTask ID、状態、履歴を作成する。コード上では個別課題であり、7枚を7点へ合算するモデルではない。各課題の0〜7点入力は今回の指定に従う。

対象は `subject === "math" && category === "計算"`。新規attemptに `taskId` と表示用スナップショット `taskLabel`（例：第1回 / 計算①）を保存。教科・カテゴリ・課題IDは推測しない。

カードの「3回」等は `task.history.length`。従来の学習セッション件数であり、計算attemptの解き直し回数へ置き換えない。タスク完了状態は従来どおり手動変更。7/7の達成表示とは独立。

## 3. 結果登録操作

1. 学習 → 回を選択 → 算数の計算カードをタップ。
2. 「計算をはじめる」。初回保存後は「解き直しをする」、7/7到達後は「もう一度挑戦する」。
3. 「計算を終了して結果を記録」。
4. 0〜7の得点を選択し、得点・所要時間・JST開始日を確認。
5. 「この結果を保存」。詳細を閉じなくても次の解き直しを開始できる。

途中記録はfamily / UID / 課題 / 開始日で分離。画面を閉じた場合やreload後は計測を休止して復元し、採点途中はそのまま復元する。保存失敗時も下書きを保持。同じattempt IDの再送は既存の保存結果を返す。閉じた画面で遅れて完了した保存は、新しい下書きや別画面の計測状態を消さない。

## 4. 実績の表示

JST実施日・課題別に、初回得点／時間、最新得点／時間、最高得点、解き直し回数、7/7到達を表示。異なる課題の得点を合算しない。

「日ごとの記録」の行を選ぶと日付・課題が選択され、詳細へスクロールする。詳細には選択課題のグラフと、その日の全課題・全attempt一覧を表示。初期表示、Firestore更新、課題セレクトだけの変更では自動スクロールしない。

直近30の記録日を読み込み、「もっと前の日を見る」で以前の記録日も読める。既存の日別summaryは日付を探すために利用し、課題別の実績値は全attemptから導出する。

## 5. 4種類の推移

| グラフ | 使用データ |
| --- | --- |
| A 日付ごとの初回得点 | 選択課題の各JST日、初回得点0〜7 |
| B 日付ごとの初回時間 | 同じ初回attemptの所要秒数 |
| C 日内の得点 | 選択課題・選択日の全attempt |
| D 日内の時間 | Cと同じattemptの所要秒数 |

初回・解き直し1回目・2回目…を区別。得点と時間は別グラフ。対象問題数が違う場合は時間だけで比較できないことを明示し、短時間・低得点を自動的に改善と評価しない。既存Rechartsを使用し、package追加なし。

画面検証では、日別3点×2グラフ、日内14点×2グラフについて、実際のSVG描画位置を保存済み得点・秒数と照合して一致を確認。履歴一覧も同じ保存済みattemptを使用。tooltipのクリック表示は確認済み。iOS実機のタッチ操作は未確認。

## 6. 解き直し保存方式

既存 `commitCalculationAttempt` のtransactionを継続使用。UID／JST日内のappend-only通番 `attemptNo`、既存 `attemptType`、初回保持・最新更新・最高点保持を維持。同一IDの再送・複数クライアントの同時保存に対応。

課題別の試行番号・初回／解き直し表示は、同じ日・課題の全attemptを保存済み通番順に並べて導出する。元の通番・既存attemptは書き換えない。追加回数に上限なし。7/7後も保存可能。

## 8. 既存データ互換性

課題IDのない既存attemptは「課題未指定」として表示し、推測で①〜⑦へ割り当てない。削除・履歴上書き・migrationなし。Taskが後で削除された場合も保存済み表示名から履歴を表示できる。

## 9. 学習時間・報酬

計算attemptの時間は従来v1.86どおり、学習時間・活動P・fan・週間ガチャへ加算しない。既存学習タイマーは計算カード内にも維持し、その保存だけが従来の学習履歴・時間・報酬の対象。

学習タイマーが動いている場合や対象課題に未保存の学習時間がある場合、計算のSTARTを停止。計算計測中は既存学習タイマーの開始を無効化。計算attempt保存ではTask履歴を追加せず、カードの回数表示を変更しない。

計算attemptは専用計測なので、対応する新規学習sessionIdは作成しない。通常の学習セッションの15分idle STOP・背景観測・確認待ち・時間修正・0分確定・二重報酬防止は変更していない。
