# v1.89.15 verification

## Behavior

- WBS shows completed 100%, explicit manual progress, measured progress, initial 0%, or unknown. Initial 0% is presentation only; manual 100% does not complete a task.
- Target dates are edited inline. The standard date is Thursday before the next Friday round switch, with later lesson dates handled as exceptions. First attempt/grading, conditional correction and final review are estimated without reducing the required work to fit capacity.
- Target edits append `planning.targetRevisions` and archive an existing task baseline in `baselineHistory`. Imported baselines are also captured in the revision snapshot. Saving checks both task revision and adopted schedule pointer in the transaction.
- `Baseline.basisStatus` is optional. `unmeasured` permits a provisional date-only target with empty daily weights. It does not create a purple progress comparison. Existing native plans remain compatible.
- Feedback export includes target revisions, baseline history and task planning revision. Local proposal imports cannot overwrite these task-side adjustments.
- Red solid and purple dashed lines use measured actual progress and adopted daily work/fixed targets. Manual reference differences are separate. Dates alone never imply daily progress weights.
- The primary update button opens the file chooser directly. Safe files save through the existing transaction; errors keep the grid and explain why saving stopped. Reference proposals remain reference-only.
- Authorized round-11 priority adoption validates ten task identities, nine staged tasks, one completed task, source approval, account binding, base revision and conflicts. Changes in task status, new actual records, running timers, manual dates or fixed baselines stop adoption. Same revision/content is idempotent.
