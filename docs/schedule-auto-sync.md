# 家庭教師計画の自動同期

## 家庭教師が公開する

1. 本番から採用計画、課題、実績、手動予定、固定目標、確定期限を取得します。新しく登録された回と課題は次の計画作成に使います。
2. `02_candidates` に `learning-schedule/1` 形式の日別範囲を保存します。実taskIdと認証アカウントを照合し、`baseVersion` は現在の採用計画の `planId--r番号`、元計画の `planId` は前回と同じ系列、`revision` は前回より大きい整数にします。仮の学習枠、未配置時間、未確認事項は `provisional` と `gaps` に残します。
3. 検証が済んだJSONだけを公開します。取得日時は計画を作った時刻ではなく、根拠にした本番データの読取時刻です。

```powershell
node dist-ssr/schedule-sync/run.js publish $integrationRoot '02_candidates/<検証済み候補>.json' '<本番読取日時のISO 8601>' '第14回'
```

公開コマンドはルートの `SYNC_READY.json` を一時ファイルから置換します。SHA-256は候補JSONのファイル全体に対して計算します。`ready`、対象回、取得・作成日時、暫定設定を照合して処理します。公開済み候補の修正は新revisionにしてください。未登録課題は同じtaskIdと識別情報で登録されるまで保留します。実績変更・期限・手動予定で保留された課題は、新しい本番取得結果から再計画してください。

## Windowsの実行

CLIは `npx vite build --ssr scripts/schedule-sync/run.ts --outDir dist-ssr/schedule-sync` でビルドします。Webビルドの出力先とは別に置きます。本番アプリと同じFirebase project、家族、利用者を `04_private/schedule-sync/config.json` で指定します。このフォルダはWindows利用者とSYSTEMがアクセスできるようにします。

```powershell
& scripts/schedule-sync/run-windows.ps1 -Mode connect -Config $config -Runner $runner
& scripts/schedule-sync/register-task.ps1 -CheckOnly -Config $config -Runner $runner
Start-ScheduledTask -TaskName 'Study Schedule Auto Sync'
```

初回接続はWindowsで既存アカウントを入力します。パスワードは保存せず、Firebaseの利用者セッションをWindows DPAPI CurrentUserで暗号化します。読み書きは同じ利用者のSecurity Rulesを通ります。接続が失効した場合は接続手順を再実行します。

読取確認に成功してから `-CheckOnly` を外して登録し、同じタスクを起動します。無人実行を確認したネイティブの `codex.exe` は `-TutorCli` に絶対パスで指定します。省略時は再計画要求を保存します。15分ごととログオン後に実行し、同時実行を抑止します。停止・ログオフ中の候補は次回ログオン時に照合します。タスクは登録時のCLIを使うため、ビルド配置を変える場合は登録も更新します。

## 差分からの再計画

- `apply` は `LATEST_DIFF.json` の前回スナップショットと本番を比較し、新規回・課題・完了・採点や直しを含む進捗変更・確定期限超過を記録します。初回は従来レポートの直近差分も引き継ぎます。`check` の結果は `LATEST_CHECK.json` に保存し、比較元を進めません。
- `04_private/schedule-sync/requests/<入力ID>.json` に要求を保存します。同じ入力では家庭教師を再実行せず、作業範囲・期限・採用計画や、候補に関係する学習枠が変わると再評価します。`no_safe_plan` は配置できる候補がない場合、`cli_failed` はCLIを実行できなかった場合に記録します。`cliStarted` でプロセス起動の有無を確認できます。
- 今日から7日間は、保護者確定枠（0分を含む）、採用済みの当日枠、曜日別暫定枠の順に使います。暫定枠は月10・火25・水10・木40・金15・土30・日20分です。既存予定を差し引いてから候補を作り、使った日の容量だけを候補に含めます。
- `LATEST_DIFF.json` の `replanEvaluation` に、未配置課題ごとの理由と配置可能件数を記録します。家庭教師CLIは検証できる日程がある場合に起動し、範囲、時間、進捗率、期限を番号で渡します。範囲や所要時間が未登録の課題は未配置のまま扱います。端末にしか保存されていないイベントは、本番の課題・採用計画・既定カレンダーに期限が反映されたときに検出します。
- ガントの「保護者：学習範囲・所要時間の確認」では、回・教科を選んで複数の未登録課題に範囲・作業量・予定分数を入力し、入力済みの行をまとめて確定できます。確定入力は既存課題の未配置範囲として保存し、次回の同期で照合します。
- 課題名の明示範囲、確認済み問題数、実taskIdとの対応確認済みの資料は、出典を添えて候補表示します。採点済みで同教科・同教材・同作業量の初回と直しの履歴をそろえられた場合は仮見積を使います。採点だけを計った履歴は現行形式にないため、別の分数を加えません。仮見積による配置は学習開始前の課題に限定し、採用元の候補と差分レポートに根拠を残します。
- 候補は既存の部分計画の照合と日別容量の検証を通し、学習実績・手動予定・確定期限・固定目標を保護します。候補の検証後に本番と公開元を再確認し、変更があれば公開を見送ります。公開できた候補は `SYNC_READY.json` から次回のWindows同期で採用判定を受けます。候補が成立しない場合は採用中の計画を維持します。

## 照合と確認

- 既存の計画取込・transactionを使い、選択した変更だけを `tutor-sync-v1` の新しいrevisionに保存します。元の家庭教師revision、適用・保留の課題と根拠を保存します。
- 保存直前に採用ポインタ、関係課題、学習枠、同期状態を再照合します。競合のない追加課題は学習回ごと保持し、日付を割り当てていないものを差分に記録します。
- `04_private/schedule-sync/LAST_RUN.json` に直近の実行結果、`LATEST_DIFF.json` に新規学習回、課題の更新、未配置、登録待ち、保留理由を保存します。変更があった回の差分は `reports` にも残します。採用前後には計画と課題の照合結果を別ファイルに保存します。
- 同じ公開内容と本番状態で再実行すると、Firestore書込みは0件です。登録待ち課題が同じIDで登録された場合だけ、同じ候補の該当部分を再照合します。
- 予定と実績は従来のガントで確認します。自動同期は予定を取り込む処理で、家庭教師の学力分析は別に行います。
