## 画面・使い方

下部は「学習／実績／成績／プロデュース／対策・復習」の5タブ。成績は独立したまま。

復習ホーム上部は開始ボタンと今日の状況、中央は保護者の苦手情報・間違い直し・問題一覧・最近50回答の履歴。保護者用の登録・編集は下部の破線枠の折り畳み内。解答中は管理画面を表示しない。

1回最大5問。5問未満は実数を明示し、重複して増やさない。1問ずつ候補を選び「回答を決めて次へ」で確定し、最後にまとめて採点・解説。確定後の前問修正は行わない。3分は目安で、終了制限はない。0問正解でも肯定的な表示をする。

所要時間は開始から最後の回答までの経過時間（タブ移動・reload中の時間を含む）。各問の確定までの時間も保存する。通常学習時間には加算しない。

回答確定ごとに端末の途中経過を保存する。端末保存キーはproject/family/UID/sample-liveで分離。タブ移動・reload後も復元する。保存不能時は警告する。未確定の選択肢は復元しない。「今回はここで終わる」から削除確認を経て未保存の途中経過を破棄できる。端末をまたぐ途中回答の同期は初期版対象外。

採点後に「結果を保存する」でFirestore保存。失敗時は同じボタンで再試行。保存成功後に間違えた問題だけ再挑戦できる。直後の正解だけで元テストの弱点を解消扱いにしない。

## 問題登録・取り込み

保護者操作で四択を手動登録・編集できる。教科・単元・問題文・選択肢4件・正解・短い解説・テスト種別・任意の出典を入力。編集はIDを保持しversionを更新する。進行中に問題が編集された場合は旧版の新規保存を拒否し、保存済み回答を保持してやり直しを案内する。

一括取り込みは下記の**項目をすべて持つJSONオブジェクトの配列**。1〜50問、入力文字数200,000以下。これは形式説明用のプレースホルダーで、そのまま実問題として登録しない。

```json
[
  {
    "subject": "math",
    "unit": "保護者が確認した単元",
    "prompt": "保護者が提供する実際の問題文",
    "choices": ["選択肢1", "選択肢2", "選択肢3", "選択肢4"],
    "correctIndex": 0,
    "explanation": "保護者が確認した短い解説",
    "testKind": "未指定",
    "source": ""
  }
]
```

- subject: `math / japanese / science / social`。
- correctIndex: 0〜3の整数（0は選択肢1）。testKind: `未指定 / 判定 / 組分け / カリテ / その他`。
- 単元100、問題文1000、各選択肢300、解説1000、出典300文字まで。出典以外の文字列は空白のみ不可。選択肢は前後空白なし、4件が異なること。
- ID/versionはアプリが発行。未知フィールド、未知教科、重複、配列数、正解範囲、文字数等の不正は、書き込む前に全件を検査して拒否。Rulesでも形状・型・長さを検証する。
- 同一JSONの再試行は同じID/versionを使う。取り込みはtransactionで原子的に保存し、成功応答消失後の同版再試行は再登録しない。
- 表示上限は本人UIDにつき問題200、苦手100件。UIは超過登録を拒否し、読み込みも上限超過を明示して停止する。Rulesによる全collection件数制限ではない。削除・自動アーカイブは初期版対象外。
- サンプルの架空問題は既存サンプルモードに限定。Emulatorテストの架空問題はテスト専用ファイルに置く。本番用の初期問題は含まない。

苦手情報には教科・単元・観察した誤答・復習ポイント・テスト種別・対応問題最大5件を保存。事実と推測の判断、長文読解・複合問題の改善確認は保護者の外部分析で扱う。

## 出題と改善記録

選定は①前回不正解、②保護者が関連付けた未回答／期限到来問題、③その他の未回答／期限到来問題、④最近正解できた問題の順。同じ優先度の中をランダム化して最大5問にする。四教科の問題が対象だが、登録状況に応じて全教科を毎回必須にはしない。

通常の正解は3日後、直後の再挑戦の正解は翌日、不正解は次回を確認予定にする。期限前に正解済みの問題は優先度を下げる。必要な問題数に満たないときは低優先の問題も利用する。問題IDは一回のセッション内で重複させない。

履歴には問題ID/版、対象UID、日時、選択、正誤、所要時間、通常確認/直後再挑戦、当時の問題・正解・解説を保持。進捗には初回正誤、前回・最新正誤、件数、次回予定を保持する。後から古い回答が到着しても、より新しい日時の進捗を巻き戻さない。編集後の問題は未確認として扱い、初回の記録自体は保持する。

ホームの今日の件数と履歴は**最近50回答の範囲**であることを表示。全履歴はFirestoreに残り、復習候補は全問題の進捗から判断するため、古い未解決問題が履歴表示の上限で消えることはない。

## 保存・Rules・分離

`families/{familyId}/reviewUsers/{uid}/` 以下を使用する。`reviewUsers/{uid}`の親文書作成は不要。

| Collection | 内容 | 許可 |
| --- | --- | --- |
| questions | 問題マスター、ID・version | 本人R/C/U、削除不可 |
| weaknesses | 保護者の観察・対応問題ID | 本人R/C/U、削除不可 |
| attempts | 問題ごとの追記専用履歴、ID=`sessionId_0..4` | 本人R/C、変更・削除不可 |
| progress | 問題ごとの最新状態・累計 | 本人R、対応履歴と一緒のC/Uのみ |

すべてで `isFamilyMember(familyId) && request.auth.uid == uid` を要求し、getとqueryも同様。他の家族・同一家族の他UID・未認証は拒否。既存のfamilies/tests/tasks/game/rewardLedgerのRules・データは変更しない。既存データのmigrationは不要。

回答1件と進捗1件を1 transactionで保存する。1問につき3文書読取（履歴・進捗・問題）と2文書書込、5問で基本15読取・10書込（競合再試行やRules参照を除く）。5問を一つの巨大なatomic batchにはしない。Rulesは正解を問題から照合し、対応する新規履歴・進捗・件数の整合をgetAfterで検証する。参照先は家族・問題・回答・進捗。キャッシュ前の呼出し数でも履歴側最大7・進捗側最大4で、1書込10・transaction合計20の制限内に収め、正常系をEmulatorで実証する。

固定IDで重複回答を拒否し、既存と一致する再試行は成功として扱う。部分保存で止まっても未保存の問から再開する。別端末で進捗が先に進んだことをサーバーで確認できる場合だけ、Rulesによる競合拒否を限定再試行する。

読込はサーバー確認を要求し、キャッシュだけを成功扱いしない。タブ表示時と保存後に取得し、常時listener/pollingは置かない。通常1回の全読込は問題数＋苦手数＋進捗数＋最近50回答（最大550文書、空query・Rules参照等は別）。回答履歴は1問1文書で増加する。無料枠への影響は既存学習・ゲーム分と合算であり、無料枠内を保証しない。公開レビュー時に件数と利用頻度から評価する。

v1.86.4由来の `useFamilySession` を再利用する。UID変更前に保護UIを外し、UID固定のFirestore clientを破棄する。非同期結果はsession.activeとmountを確認し、旧UIDの情報を新UIDへ反映しない。キャッシュキーも分離する。

**保護者専用のrole/認証は既存にない。登録枠はUI上の区別であり、保護者だけの権限制御ではない。** 保護者は復習する本人の認証で登録する。同一家族の別UIDを保護者権限として扱わない。解答はクライアントに存在し、不正解検知を試験監督用途の保証には使わない。復習に活動P・ファン等の報酬は付与しない。
