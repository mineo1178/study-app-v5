# 対策・復習：資料に基づく選定と間隔反復

個人資料・成績・個別計画はリポジトリや公開バンドルに含めない。保護者が資料と照合した計画JSONを、対策・復習の「この端末のテスト対策計画」から取り込む。計画は project / family / UID / sample 別の localStorage に保存し、Firestoreには送らない。別端末では再取込が必要。

計画の形式は `src/review/target-plan.ts` の `TargetPlan`。問題IDとversionを完全一致させ、優先度・子ども向けの選定理由・誤答の根拠・範囲との関連を記載する。対象外・版違いの問題では補充しない。テスト日翌日以降は計画を見直すまで候補を出さない。未設定時は一般復習と明示し、テスト適合や苦手を推測しない。

今日の候補は最大5問。期限済み、期限が古い順、計画の優先度、IDの順で選ぶ。未回答は期限済みの後。読み込んだ全Progressで当日の回答済み問題数を差し引く。同時に異なる計画を使う複数端末をまたいだ「1日5問」の厳密なサーバー制限ではない。報酬や学習時間は付与しない。

不正解は翌日のJST 00:00、初回の通常正解は3日後。同じ版の問題で期限を迎え、前の判定日と異なるJST日に通常回答で正解したときだけ、3→7→14日と延ばす。14日後も確認を続ける。不正解なら翌日に戻す。同日・期限前の正解やretryは段階と期限を進めない。四択の正解を、元のテストの技能全体の解消・定着と表示しない。

## 保存互換性と公開前条件

- 回答履歴の形式・ID・保存先は不変。問題や苦手情報の登録権限は追加しない。
- Progressの既存フィールドを保持し、`reviewStage`（0～3）、`reviewDay`（JST日番号）を追加する。
- 旧Progressは次の保存時に保守的に段階0から移行。旧誤答・直後再挑戦は翌日まで出さない。履歴の書き換えや一括migrationは不要。
- 既存の回答＋Progressを結ぶ2書込transaction・固定attempt ID・競合時の再読取を維持。古い回答の遅延到着は件数だけ増やし、新しい期限・段階を戻さない。
- Rulesは計算した段階・判定日・期限との完全一致を検証。旧形式は移行前のみ許可し、一度移行したProgressの旧形式への降格は拒否する。このため旧アプリの開きっぱなしのタブは更新が必要。
- 本番公開には対応Rulesとアプリを合わせた承認が必要。この作業でRulesのdeploy・本番書込みは行わない。個別計画の対象テスト名・正式範囲と不足問題の内容は別途確認する。

## 対象検証

`src/review/model.test.ts` / `target-plan.test.ts` でJST境界、段階・不正解・同日・期限前・版変更・旧Progress・不足・期限切れを確認する。

`tests/review-spacing.emulator.ts` / `test-review.emulator.ts` で旧データ、transaction、同時保存、再試行、偽装拒否、UID・family分離を確認する。

`scripts/test-review-spacing-browser.mjs` はlocalhost専用。通常は架空資料で動作し、任意の非公開ファイルで選定の実照合も可能。非公開ファイルの内容は出力せず、スクリーンショットも保存しない。320/390px、reload、失敗再試行、期限・段階、UID切替、既存学習・ゲームの不変性を確認する。
