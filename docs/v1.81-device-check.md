# v1.81 実機確認（約8～10分）

同じアカウントを使い、実データでの確認は未実施の学習課題で行う。開始時刻をメモし、記録は最後に1回だけ保存する。

1. スマホでSTART。1分表示を確認し、画面OFFで2分待つ。復帰後、計測中のまま約3分になっていることを確認。
2. そのまま別アプリへ2分移動。戻ると約5分で、STOPされず、時間が巻き戻らないことを確認。
3. ページを再読み込み。約5分から計測が続き、0に戻らないことを確認。
4. 別端末Bがあれば、同じアカウント・課題一覧を開く。Bで別課題をSTARTし、両端末で新しい課題だけが計測中になることを確認。Bで一時停止し、Aで停止状態が反映されることを確認。
5. Bで再開し、1分程度後にSTOP・記録保存。A/Bを更新し、保存した課題の履歴が1件で、時間が重複していないことを確認。その課題の累計が10分未満なら活動P対象は0が正常。単独端末なら手順4を省略し、そのままSTOP・記録保存する。

有効時間は既存どおり10分以上。30分以上のbackgroundは要確認フラグの対象となるため、この短い確認では避ける。実施中の計測時間も学習記録になるため、実際の学習中に確認する。

## 自動確認の範囲

visibilityイベント、tickなしの絶対時刻計算、復帰、保存データ復元、同時STARTの開始時刻・IDによる選択、クラウド状態の統合、停止対象をstate変更前に確定する処理は単体テストで確認。

複数クライアントの状態統合をモデル化したテストであり、Firestoreの通信・transaction競合を再現するemulatorテストではない。本リポジトリにはemulator構成がなく、実Firestoreの複数端末書込みは未検証。

## 残る競合リスク

タイマー書込み・履歴保存・オフライン再送は既存のupdateDoc／batch方式。古い端末の遅延STOPが同じ課題の新しいセッションを上書きする場合や、両端末の同時履歴保存、未送信操作の再送順について原子性・二重計上防止は保証できない。購読による同期は書込み自体を原子化しない。

この項目を確認する追加テストは、上の通常確認とは分ける。A/Bで同じ課題をほぼ同時にSTART／STOPするケースと、AをオフラインにしてBで再開後Aを復帰させるケースを確認し、問題があれば時刻・課題名・操作順・履歴件数を控える。

## v1.82候補

既存タスクdocumentのsessionStartTimeを照合するtransactionで遅延STOPを防止し、履歴保存とオフライン再送の競合をemulatorで検証する。schema変更を伴う排他設計は別途検討が必要。
