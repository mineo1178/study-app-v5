## Measurement and ownership

TaskPlan optionally stores questionMeasurement, questionPlan and questionGoal with append-only histories. Existing task revision and schedule-pointer transactions are reused. Quantity saves never change task status, learning time, grades stored in the timer history, rewards or task IDs. No Rules change or migration.

The user authorized provisional equal stage weights (first attempt / grading / mastery = 1 each). With a confirmed scope and total N, confirmed counts F/G and classified error count R/self-solved redo count D, mastery K=G-R+D; progress=(F+G+K)/(3N). Redo never increases N. Graded=0 explicitly implies confirmed mastery=0, without declaring corrections unnecessary. For graded>0, unknown errors remain unknown and do not yield a precise percentage. No-errors requires an explicit post-grading confirmation.

Question-plan daily quantities total N in each stage, with cumulative grading <= first and mastery <= grading. Formal comparison requires matching scope identity, total and weights. Existing legacy baselines are not reinterpreted as three-stage quantities. New quantity goals require a separate explicit action/reason and preserve history. Manual progress stays separate and has quick 0/25/50/75/100% presets.

The optional ScheduleItem questionPlan and questionGoalCandidate extensions use learning-schedule/1; v1.89.17 is required to read them. Unknown fields remain null. Goal candidates never become active from file import. Pending recovery schedules show a review and stay unsaved until explicit confirmation; base version, task/account identity, actual updates and prior plans remain guarded.
