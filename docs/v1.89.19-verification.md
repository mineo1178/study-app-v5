# v1.89.19 events and completion deadlines

One non-collapsible event row sits directly under the shared date header and remains there during vertical scrolling. It uses the existing day width, horizontal scroll, 29-day period and today center. Cells are blank without events, abbreviate long labels and show a count for additional events; selection opens all names, dates, rounds and sources. Events do not enter task counts, completion, rewards or learning history.

The release bundles only the explicitly user-confirmed Nov21 curriculum test and round11 Nov12 / round12 Nov19 completion deadlines. The private timetable was rendered and visually checked; its 52 confirmed lesson/test/special/closure entries are in a separate local learning-events/1 candidate. No timetable PDF, private evidence or local plan JSON is committed. Participation is not inferred from a printed calendar entry.

The existing file picker recognizes the event format and previews event and automatic-deadline changes before an explicit save. Event references, revision guards and prior deadline changes are stored per account/project/family on the current device, separately from the adopted learning-plan pointer. Another device needs the same file imported. Same IDs and equivalent test date/kind/rounds are deduplicated; unconfirmed or malformed entries, stale revisions and changed contents at the same revision are rejected. Cancellation is explicit. The two user-confirmed historical deadlines cannot be extended by an event import.

Automatic deadlines use a confirmed explicit completion date, then the day before a confirmed next class explicitly linked as the completion basis, then a provisional last available study day before a known test. Otherwise the result is unset. These dates never become adopted daily quantities or fixed goals. Prior confirmed automatic deadlines remain in history and overdue counts after later changes. Past due plus incomplete status is distinct from an unmeasured quantity. The four-block dashboard shows the next event, an associated completion deadline, overdue and remaining work without changing red/purple comparisons.

WBS rounds derive only from real tasks. Existing DailyView curriculum creation adds round13; removing its tasks removes the round even if a planning scope mentions it. New groups start collapsed. Descending rounds, subject order, task creation, timers, grading/redo, manual dates, fixed-goal histories, Firestore rules and the adopted r3 stay intact. The mobile return area and event row use compact spacing so the chart remains reachable with the four summary blocks.
