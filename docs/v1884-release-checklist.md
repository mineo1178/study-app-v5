# v1.88.4 / Design 2.2 公開前チェック

この文書は手順の確認用。本番Rules適用・mainマージ・Production公開は別途承認が必要。

## 保存互換性

| Rules | クライアント・Progress | 結果 |
|---|---|---|
| 現mainの旧Rules | 旧形式の回答＋Progress | 保存可（localhost実測） |
| 現mainの旧Rules | 新形式reviewStage/reviewDay付き | transaction全体が拒否され、回答・Progressは部分保存されない（localhost実測） |
| 新Rules | 未移行Progressへの旧形式保存 | 許可（Emulator検証） |
| 新Rules | 新形式保存・旧Progressからの移行 | 許可。回答履歴は維持（Emulator検証） |
| 新Rules | 移行済みProgressを旧形式へ戻す保存 | 拒否（Emulator検証）。旧タブは更新が必要 |

問題ID・version・回答ID・保存先は不変。履歴の一括移行・書き換えは不要。
新Rulesはペアの回答とProgressの整合、JSTの1/3/7/14日、UID/family分離を検証する。

## 別途承認後の適用順序

1. 対象project/database、公開commit、現Production、現RulesのリリースID・ソース・ハッシュを照合して退避する。正常なdeploymentを復旧候補として記録する。
2. 利用者に、公開後は全端末の旧タブを更新することと、未保存の回答を捨てないことを案内する。
3. 対応する新Rulesだけを先行適用し、再読取・ハッシュ照合する。旧版での未移行保存互換性を確認する。本番に架空の回答を投入しない。本人の実操作が必要なら未確認と区別する。
4. Rules検証に問題があればアプリを公開しない。別途承認されたmain反映・自動Production公開はRules確認後に行う。
5. 全端末で再読込し、旧バンドルのタブを閉じる。本人の実回答で保存と次回復習予定を受入確認する。保存失敗時は途中経過を保持し、更新後に再試行する。

案内例：「復習の保存方式が変わりました。スマホ・タブレット・PCの古い画面は更新してください。保存に失敗した回答は消さずに、更新後に再試行してください。」

## 障害時の復旧

- 新形式の保存が一度でも行われた場合、旧Rules・旧クライアントへ単純に戻さない。移行済みProgressとの互換性がなく、保存拒否や復習期限の損失につながる。
- 復習操作の一時停止を案内し、対象UID・失敗操作・適用Rulesとdeploymentを確認する。途中経過と既存データを保持し、新形式を扱える互換修正版の公開を別途承認する。
- 新形式保存前に戻す場合も、未移行であることを確認し、退避済みの正確なRules/deploymentに限定して別途承認する。推測によるデータ復元・削除、Rules緩和は禁止。

## その他の公開条件

- 既存初期5問の追加・変更・再登録は不要。問題不足や部分対応を隠さない。
- 実計画JSON・照合済み問題対応表は利用者が端末で取り込む。端末間の自動同期はない。個人成績・実UID・非公開根拠をGit/Previewへ含めない。
- 試験翌日JST 00:00から一般復習へ戻し、保存済み計画・revision・Progressは保持する。
- Previewのサンプル操作、実機Safari/iPadの表示・操作・保存を確認する。localhost Edge E2Eやviewport検証を実機SafariのPASSと扱わない。
