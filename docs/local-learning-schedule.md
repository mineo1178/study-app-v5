# ローカル学習計画の取込（v1.89.1）

予定の正本は私的ローカルJSON、タスク・回答・学習時間の正本は従来のFirestoreです。計画の取込は既存タスク、旧planning、履歴、報酬、旧目標を更新しません。

形式は `learning-schedule/1`。既存の復習分析用 `1.0.0` とは別形式です。定義・厳密な検証は `src/planning/schedule.ts`、非個人の例は `tests/schedule-fixture.ts` にあります。計画には planId、整数revision、generatedAt、provisional、scope、capacities、items を含めます。itemsには既存taskId、回・教科・カテゴリ・教材名・materialId、範囲ID/問題番号・ページ等のlabel、作業量、予定分、予定日、終了予定日、締切、日別量、固定目標と推定根拠を指定します。正確な範囲が不明なら、label・notes・gapsで未確認と明示します。

## 作成・取込

1. アプリの「保護者：ローカル計画JSONの取込・更新」で課題一覧を保存します。実taskIdとアカウント識別子を取得できます。UIDは出力しません。この一覧も私的資料です。
2. ローカルでJSONを作成・改訂します。新規登録教材は既存materialId、旧教材は `legacy-<taskId>` を使います。同名だけで照合しません。
3. ファイルを選択し、追加・変更・除外・不一致を確認します。宛先未指定の計画は現在のアカウントへの明示確認が必要です。アカウント識別子がある場合は一致必須です。
4. 全件検証後、アカウント専用の計画をtransactionで保存します。不一致が1件でもあれば全体を拒否します。毎日ファイルを選び直す必要はありません。
5. 更新通知はアプリで確認できる保存済みrevision/更新日時です。Windows上のファイル変更は自動検出しません。ローカル更新後はファイルを再選択してください。

## 改訂・実績

同じrevision・同じ内容は再保存不要。同じrevisionの内容変更や古いrevisionは拒否します。新revisionは実績を上書きしません。旧計画と固定基準は `learningSchedules/<認証UID>/plans/<planId>--r<revision>` に変更不能で保存します。最新revision台帳も単調増加です。計画変更時は旧基準を残したまま、新revisionの基準を記載します。

範囲終了・採点・直しは既存タスクの追加フィールド `scheduleActuals.<rangeId>` に記録します。課題全体のstatus、タイマー時間、学習履歴、報酬は変更しません。進捗率は採点・直しまで終わった量／全量。未測定は推測せず表示し、既存completedは100%を優先します。赤・紫とも同じ実績を日別予定量・固定目標の累積と比較します。＋は先行、−は遅れ。

入力訂正は新revisionで行います。実績のある範囲IDについてlabelやunitsを変えることは拒否します。範囲の意味や作業量を変更する場合は新しい範囲IDを使い、旧実績は残します。日付や予定時間の訂正では同じ範囲IDを維持できます。日付の一時変更は提案JSONとして出力し、ローカル計画へ反映して再取込します。

## 保存・権限

Firestore Rulesは認証済み家族かつ本人UIDのみ計画の読書きを許可します。取込は最新ポインタ・変更不能版・revision台帳の3文書を原子的に作成します。クライアントは既存taskIdと回/教科/カテゴリ/教材識別を再照合します。実績保存は現在の計画revisionと範囲IDをtransactionで再検証し、変更したフラグだけを最新の実績へ合成します。保存失敗では従来データを保持します。大規模移行・新しい外部同期はありません。

実計画JSON・課題一覧・個人資料はGitへ入れません。保護者がファイルを確認して取り込むまで、本番の予定は自動変更されません。
